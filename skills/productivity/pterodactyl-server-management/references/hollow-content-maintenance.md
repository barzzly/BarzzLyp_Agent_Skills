# Hollow content maintenance

- Fresh Pterodactyl contents GETs can return stale cached logs. Add a unique `_t` query parameter and require fresh command timestamps before judging native effects or restart readiness.
- Compare marker coordinates against an older untouched world snapshot: Hollow uses hundreds of decorative lodestones. Identify newly added altar blocks by coordinate diff, never replace every lodestone.
- Take final region snapshots after confirmed server shutdown so pending player edits are flushed. nbtlib parsed LongArray can be read-only; replace with a fresh LongArray rather than assigning an element. Preserve non-marker blocks at old virtual points, including gray carpet. Verify chunk block-state differences remain restricted to authorized coordinates.
- RukhDungeon prepares PRIVATE copies by clearing waypoint/point cells. Native one-cell CLOSED LODESTONE gates can restore altar interaction cells; update their regions alongside waypoints and boss triggers. An INTERACT objective can launch a three-spawn zero-delay wave and complete only after the wave clears, without changing BossService.
- Native RukhDungeon chest views historically use independent entry chances, not min-items/max-items weighted rolls. Explicit Nexo pool count settings and provider support are needed for 2–3 unique materials plus independent vanilla fillers. Preserve these settings in serializer and both loot editors; construct items before consuming a personal claim.
- Nexo 1.25 exposes static NexoItems.itemFromId(String), ItemBuilder.build(), and NexoItems.idFromItem(ItemStack). Clone built stacks before changing amount. Mythic physical drops use `nexo item_id amount weight`; TotalItems: 2 makes drop weights selection weights. Boss give order is `nexo give item_id amount players`.
- For a boss-spawn reward chest, register a personal chest with required boss objective and a one-cell OPEN gate whose closed-material is CHEST. Initial AIR clears the eagerly initialized chest; CLOSE_GATE on boss completion materializes it without blocking the spawn. Verify actual boss-death chest interaction separately from native loot rolls.
- Freeze party-scaled wave targets per spawn in session state at launch; use those targets for fill, objective totals and missing-entity recovery. Keep unscaled waves on legacy maxAlive recovery semantics so multi-entity providers are not regressed. Never multiply cursed boss wave unless requested; preserve scale flags through YAML roundtrip.
- Permit pearl movement on the same side of a closed gate using template-coordinate segment/cuboid checks with player-size padding. Preserve chorus restrictions and cross-session isolation; geometry tests alone do not prove native projectile throwing or every over-wall route.
- Remove Historical healing from randomskill lists without deleting other attacks; disable direct calls plus shared healing routines, and inspect child-heal mechanics too. Set all eight combat definitions to requested HP, not hitbox/VFX helper entities.
- Label weighted material values as relative weights, not independent percentages. Per-player independent rolls may coincidentally match; do not promise all players receive different loot.
- Verify live item identity/quantity via bounded native rolls without granting items. Distinguish this from player chest interaction, real boss combat and onDeath reward fan-out; these require separate live encounter checks. A successful loot probe and YAML validator do not verify entry-time spawn timing. Remove self-disabled temporary checker artifacts after retaining receipts.

## Unexpected mob immediately on entry

1. Download fresh `spawner.yml`, `objectives.yml`, and `config.yml` with a unique cache-busting query; retain untouched bytes.
2. Build the union of `waves.*.spawn-points`. List each spawn point absent from that union with no `wave` or `objective` binding, including its coordinates and mob ID. Compare against the reported location and old chest coordinates, not only visible model names.
3. Confirm the native entry path: `SessionService.start()` activates points whose `objectiveId()` and `waveId()` are null and which are absent from every wave. Treat this as intentional ambient-spawn semantics; remove the obsolete definition rather than globally disabling ambient spawns.
4. Before removal, assert exact point identity/location, no wave references, and unchanged retained wave definitions. Keep a regression check that all intended encounter points remain bound; allow explicitly approved ambient points instead of deleting every unbound point blindly.
5. Respect active-run pinning and the user's interruption choice. After an authorized edit/reload, read back the exact point's absence, unchanged retained points/waves, desired enabled state, and fresh native validation. Report old-instance behavior separately until a new entry is checked.
