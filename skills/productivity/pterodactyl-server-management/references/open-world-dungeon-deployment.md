# Deploy persistent PUBLIC dungeon worlds

1. Inventory target server, world manager, dungeon-plugin binary and live config. Preserve unrelated dungeon templates and premium plugins. Record initial power state. Confirm world folder differs from existing world names, then import/load via existing world manager; verify log and world registry. If extracted world files are owned by a different UID, repair only target directory permissions through panel chmod before import, and restart once if a failed import left a session lock.
2. Inspect Anvil blocks at candidate points before generating YAML: solid non-waterlogged floor, two or more air blocks overhead, dry surrounding pad for bosses, and no air/lava/water placement. Check world region files against target after import if server has generated chunks. Keep PUBLIC arena boundary within engine chunk cap and all points inside it. `mode: PUBLIC` needs one loaded shared world, one arena boundary, `timer.enabled: false`; set `public.chest-cooldown-seconds: 60` for a shared per-chest minute and `arena.spawn-interval-seconds: 3600` with `public.boss.enabled: true` for one scheduled boss. This interval begins after enable/death, not at a fixed wall-clock hour. Multiple independently scheduled RukhDungeon bosses in one definition are unsupported; use Mythic named spawners for additional positions.
3. For Mythic named boss spawners, write **one spawner per YAML file** under `plugins/MythicMobs/spawners/`; a combined file with multiple top-level definitions may load only its first entry. Set `World`, fixed X/Y/Z, `Radius: 0`, `MaxMobs: 1`, `Warmup: 3600`, player activation range, and appropriate cooldown semantics. Reload/start, compare loaded-spawner count with expected count, then run `/mm s info <name>` for every name. Do not treat a console create response as proof that all points persist across restart.
4. Add arena-local mobs to RukhDungeon `spawner.yml` with zero jitter on verified positions, `respawn-enabled: true`, bounded `max-alive`, and chosen respawn ticks. For world-wide kroco outside PUBLIC arena bounds, use separate MythicMobs named spawner YAMLs instead: RukhDungeon owns/tracks spawns only within its session arena, and outside mobs can be rejected. Distribute named spawners across region-file candidates with 3x3 solid dry floor and three air layers; set Radius: 0, MaxMobs: 1, CheckForPlayers: true, and a bounded activation/leash range. Mythic named-spawner Cooldown is seconds; verify `/mm s info` after reload. Add loot tables and many chest positions to new `lootchest.yml`. PUBLIC cooldown is global per dungeon/chest, not personal. YAML chest points alone do not create physical blocks in PUBLIC mode: place each with `execute in minecraft:<world> run setblock <x> <y> <z> chest keep`, count successful placements in console, and avoid replacing structures. Keep the original world files untouched locally.
5. Upload new files only, read back bytes, reload plugins, run `/rd validate <id>` and `/rd list`, inspect fresh plugin logs and loaded spawner details. Confirm actual remote running state and restored original power state, then report gameplay untested until a player tests boss death, mob respawn and chest claims.
