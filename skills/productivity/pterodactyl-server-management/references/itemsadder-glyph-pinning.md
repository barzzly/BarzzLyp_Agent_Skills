# Stable ItemsAdder Unicode and consumers

- Inventory every `font_images` entry in contents YAML and compare explicit `symbol` to `storage/font_images_unicode_cache.yml`. Preserve existing cached characters; renumbering breaks literal LuckPerms prefixes, scoreboards and stored items.
- Add missing `symbol: "\uEXXX"` only, using YAML AST source positions to preserve comments and order. Assert parsed equality after removing symbol keys, unique IDs/codepoints, full mapping coverage, remote original unchanged before upload, and byte readback after writing. Back up each changed config first. Keep a runnable assert-based inventory/validation script.
- Verify live LuckPerms through fresh `lp export`, decompress `.json.gz`, and compare highest active context-free prefix per group to the pinned rank glyph. Leave valid prefixes, permission nodes and inheritance untouched. Export can contain obsolete contextual prefixes; do not clear them globally merely to tidy.
- Audit TAB group aliases, scoreboard rank placeholder, custom-font namespaces, chat format placeholders and icon conditions. Reject nonexistent `%img_*%` IDs and self-referencing false branches. Correct group-name spelling/case against live LuckPerms, not assumed rank labels.
- Inspect actual generated ZIP bitmap providers per font namespace. PUA codepoints may legitimately repeat across different fonts; compare default-font rank symbols separately from custom title fonts. Validate ZIP CRC and all pinned symbols. If Unicode mappings stay unchanged, existing generated/player pack need not be replaced merely to pin YAML.
- Reload ItemsAdder/TAB with native commands and read a fresh completion block after the exact write. Record the pre-command log offset, then inspect all subsequent parser warnings and completion lines; HTTP 204 only acknowledges command submission. Do not reuse an earlier successful reload to certify a later file. Separate config verification, generated pack verification and graphical player rendering; no screenshot means no claim of visual verification. Report unrelated preexisting reload warnings separately.

## Bedrock parity: discover before changing presentation

1. Resolve the actual Geyser host from live backend/proxy inventory. Read its `packs/`, extensions and config; Geyser on Velocity may serve an entirely different archive from backend ItemsAdder. Download the active Bedrock ZIP and Java generated ZIP before editing either.
2. Compare Java font providers by `(font namespace, codepoint)` against Bedrock `font/glyph_XX.png` cells. Bedrock pages use a 16×16 grid; derive cell size from image dimensions. Java can assign the same PUA character to different custom fonts; flattening those namespaces can make a HUD logo display a GUI texture. Do not assume stable Unicode means cross-edition compatibility.
3. Preserve requested artwork parity. A plain-text Bedrock scoreboard is a degraded fallback, not an equivalent glyph fix; obtain acceptance before substituting it when the user wants the Java design. Scope rank/TAB repairs separately from item models, lore-stat glyphs and HUD overlays.
4. Stage a modified copy outside active `packs/`. For targeted atlas edits, assert every untouched cell is pixel-identical and every unrelated ZIP entry is byte-identical. Increment manifest header/module versions consistently so clients can distinguish revisions. ZIP CRC and remote hash checks prove artifact integrity, not correct client rendering or sizing.
5. Treat `geyser reload` as player-disrupting: it disconnects connected Bedrock clients. Obtain authorization for that impact before activation, preserve the active pack as rollback, then verify Geyser loads the exact new pack. Clients must reconnect to receive it. Staging alone is not deployment.
6. Verify the actual Bedrock client separately from Java: resource-pack acceptance, rank labels, scoreboard title/icons, HUD/logo, and unrelated item rendering. Do not claim matching baselines, widths or overlay resolution from atlas generation alone. Record unresolved font collisions explicitly rather than certifying an untested atlas rewrite.
- Paramiko SFTPFile.read() may return bytes even in mode `r`; decode explicitly or compare bytes. A bytes-vs-str assertion failure is not evidence of a failed upload. Always inspect exact remote state before retrying.
