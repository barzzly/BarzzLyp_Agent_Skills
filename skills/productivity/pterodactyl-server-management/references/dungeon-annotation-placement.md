# Dungeon annotation placement and config-only expansion

- Read Sketchfab embed HTML and HTML-unescape its hotspot JSON to recover annotation names, order, and positions; do not infer room names from broad floor bands.
- Cross-check annotation coordinates against user-owned terrain materials. Annotation positions can float or intersect glass/slabs; choose safe standing cells separately. Require support/headroom and distinguish point safety from proven traversal.
- Do not use a ceiling-within-28-blocks interior filter as the only geometry source; it omits tall halls and balconies.
- Preserve original chest positions. Use managed personal loot; exploration and spawn chests must open on arrival without a later checkpoint. Reserve progression locks for explicitly requested encounter rewards. Inspect double-chest block-state types because an unmatched adjacent chest can expose vanilla inventory.
- Discover added chest candidates from actual floor palettes and room geometry. Require solid support, headroom, nearby wall/ceiling, and an adjacent broad supported approach; otherwise a point may be safe only as a parkour jump pillar.
- Distribute exploration chests with per-area quotas and minimum spacing across elevations, wings, corridors, and perimeter alcoves; a larger count clustered beside bosses does not satisfy this user's exploration preference.
- Keep optional secrets out of mandatory objective chains and navigation waypoints. Native ENTER_REGION triggers use params.region and once:true; a subtle sound can mark discovery without revealing locations. A discovery trigger does not prove a constructed hidden room or accessible route.
- Inspect live reference loot before copying rewards. Separate stack quantities from roll counts: ×2 quantities doubles entry min/max; requested ×1.5 rolls scales min-items/max-items and nexo-min-items/nexo-max-items with explicit rounding. Report integer bounds, not exact expected ×1.5 after rounding. Preserve providers, IDs, chances and weights. Copy core reward tables for requested boss/miniboss chests; keep their multipliers explicit and lock rewards to actual encounter objectives. Exploration chests stay unlocked.
- Reserve mob spawn, boss spawn, arrival, original chest, and altar coordinates before placing new chests. Assert no solid gate occupies spawn/teleport cells and no altar shares a chest.
- Final wave must explicitly COMPLETE_OBJECTIVE for WAVE_COMPLETION; wave chaining alone does not advance objective.
- Snapshot fresh live YAML and inspect active sessions before editing. For chest-only work, assert waves, bosses, waypoints, original chests, and objective chains unchanged; otherwise a builder can silently restore stale encounter config.
- Use installed NoeDungeon JAR's DungeonSerializer.load(id, yaml) and DungeonValidator for exact headless validation. Update expected harness counts when expanding content and propagate process failures; a stale count assertion is not a validation pass.
- Deploy only affected files after backup and concurrency comparison, byte-read back targets, reload, then run live validation. Read all config files after enable: serializer rewrites multiple files, so prior hashes become stale.
- Verify final name, enabled state, chest totals, discovery-trigger totals, and preserved encounters programmatically. Supply an updated placement plan; report geometry checks separately from untested jump paths, secret access, and complete gameplay.
- Insert a REACH_REGION completion objective and waypoint at the verified parkour exit before the first kill objective; an entrance waypoint does not enforce traversal. Preserve routes rather than replacing parkour with teleport. Set arrival yaw from the start-to-route vector using the serializer convention; correct position does not imply correct facing.
- Inspect installed ObjectiveService and ActionExecutor before scheduling encounters. Supported runtimes activate non-wave spawn points when their bound objective starts; SPAWN_MYTHIC actions independently spawn owned mobs. Use one path, not both, to avoid duplicates. For a unique boss, set amount/max-alive:1 and respawn-enabled:false; count triggers, points, actions and summons across the dungeon.
- Use objective-bound KILL_MYTHIC with exact provider/target ID and amount:1 for a mandatory parkour boss. Activate it before spawning: death listeners count only the active matching objective, so early death can strand progression. Remove superseded encounters and reconnect next/required links, waypoints and reward locks. Keep harassment optional only when explicitly requested; isolate variants from shared bosses.
- Report jump paths and harasser gameplay untested unless client traversal verifies them. Readback and validators prove configuration, not gameplay. Reloaded templates apply to new runs; do not terminate active runs or claim their snapshots changed.
- Clone Cuboss skill references into dungeon namespace when summons must use no-drop minions. Remove direct commands and codex/death rewards only from new variants, never shared pack.

## Combat tuning and rollback

1. Resolve live mob IDs from dungeon spawner.yml and objectives.yml boss-triggers; follow summons into their child variants. Do not scale unused bosses or shared external pack definitions.
2. Trace each hit path before multiplying: `<caster.damage>` and `basedamage{m=1}` already inherit the mob Damage change; fixed `damage{a=...}` requires a separate edit. Scale each path once, not both base and multiplier, because double scaling compounds damage. Distinguish self-damage/deflected-projectile damage from attacks on players.
3. Interpret an additional multiplier against current live values. Record before/after values and cumulative multiplier. Back up live files, preserve HP/AI/drops, and leave one runnable parsed-equality check allowing only intended damage fields and fixed hit amounts to differ.
4. For removal of boss-summoned minions, remove every caller from stomp, hand, projectile-hit and other attack paths plus unreferenced summon definitions. Preserve independent dungeon spawns and their attack skills; verify no minion summon remains reachable from the scoped boss.
5. Compare live bytes before writing, read back exact targets, reload MythicMobs, and query `mm mobs info <ID>` for every affected variant. Inspect fresh reload warnings rather than calling any warning-free subset success. Report loaded values separately from actual player HP loss.
6. When damage still feels absent, inspect actual encounter hits before raising numbers unless the user explicitly requests scaling. Read player Health, active_effects, abilities and armor attributes with `minecraft:data get entity <player> <field>` and `minecraft:attribute <player> minecraft:armor get`; check Essentials godmode without changing it. Armor values alone do not prove mitigation is the cause; verify targeting, cancellation and current spawned mob state.
7. On a request to return to previous tuning, restore only affected damage values and fixed hit amounts from the immediate pre-change backup into fresh live files. Do not restore whole snapshots, because that can undo AI fixes, disabled summons or concurrent edits. Re-run scope assertions, byte readback and runtime mob-info checks; preserve active dungeon runs and power state.
- Keep dungeon display name exact; retaining existing dungeon ID avoids duplicate entries and lost progression unless user requests ID migration.
- Rename template worlds through native commands: inspect `mv help clone`, run `mv clone <old> <new>`, require clone success and registration, then replace exact world values across config/objectives/spawners/chests. Set instance-prefix separately to the requested token; preserve existing instances. For registration-only cleanup, inspect `mv help remove`, check players/sessions and new-world registration, then `mv remove <old>`. This unloads and removes worlds.yml entry without deleting the folder. Do not edit worlds.yml during startup or restart solely to unregister.
- Copy the live reference dungeon's display.icon basehead texture for the same menu player head; plain PLAYER_HEAD lacks that skin. Verify serializer/menu support before copying.
- Copy Historical HP/drops from combat definitions, not hitbox helpers. When types differ, state color-to-type mapping and copy exact Drops including EXP, money and material-table references. Scope edits to dungeon variants and verify drop-table existence; parsed equality does not prove physical drops.
