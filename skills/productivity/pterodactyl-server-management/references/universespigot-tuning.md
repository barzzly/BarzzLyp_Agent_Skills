# UniverseSpigot tuning on existing game server

- Read live `universespigot.yml`, `resources`, latest logs, and relevant Paper configs before tuning. Evaluate all inline `Recommended value:` comments against actual values; user wants recommended true toggles applied, not only minimal default changes. Async data-saving can be enabled when explicitly requested after backing up and checking DB/world-save risks, but leave async world ticking, inventory updates, or packet sending off without compatibility testing. Preserve gameplay-sensitive tick cadence, entity behavior, and advancements unless explicitly scoped.
- Prefer config-documented performance changes such as `performance.optimiseDataPacks`, `performance.cacheWorldConfigurations`, `experimental.reducePlayerChunkSourceUpdates`, `performance.optimiseRails`, and full-hopper throttle (`performance.hoppers.throttleFullTargetContainer`: 5 to documented 8); first four were false on NoeRPG, and latter adds a small hopper processing delay. Fixes `fixPluginPlaceholderExploits`, `fixOffHandGhostBlocks`, `dontSendKnockbackIfZero` can be separate guarded toggles; classify as correctness/security rather than promised TPS gains. Back up exact remote bytes, compare candidate YAML structurally against backup, assert only intended keys differ, write through Client API, read exact target back. Avoid treating count of toggles as proof of speedup.
- If server was already offline before task, preserve offline state rather than starting it merely to test configuration. Report deployment/read-back separately from runtime validation, and do not claim TPS/MSPT gains without live measurements and comparable baseline.
- Check concurrent updates by comparing remote bytes immediately before write; if remote changed, abort/reassess instead of overwriting.
