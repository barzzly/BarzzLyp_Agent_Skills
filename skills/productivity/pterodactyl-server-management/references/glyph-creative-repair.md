# Creative glyph nesting: verify before patching

## Scope and reporting expectations

- Treat requests to make newly generated MMOItems/Nexo items safe for native GMC duplication as prevention work. Historical vault repair is separate and cannot satisfy that request. Preserve native duplication and visible glyphs; give commands and duplication bans are not acceptable permanent substitutes.
- Report database repair, YAML changes, new companion JAR and premium-plugin replacement separately. State what changed for future items and what remains unchanged. The user expects concrete changes, not a generic claim that the issue is fixed.
- Never broaden handmade glyph-item or repaired-item test results into claims about newly generated MMOItems/Nexo items. Actual generator tests and native creative packet tests are distinct acceptance gates.

- Reproduce against exact installed Nexo and active glyph YAML before changing formatter. Clean textual placeholders can already be stable: separate legacy damaged components from new creative corruption. Preserve creative duplication and glyphs.
- Use actual inbound creative packets plus server InventoryCreativeEvent observations. Mineflayer 1.21.11 setInventorySlot can emit wrong UntrustedSlotComponent payloads while mutating local inventory; apparent client success is not server acceptance. Encode each normal SlotComponent body as ByteArray excluding its VarInt type ID. Clear target slot first so server does not skip equal-stack events; request fixture updateInventory next tick and await authoritative returned item. Assert actual events and all returned component/count/type equality.
- For legacy AxVaults 2.15.3 H2 snapshots, use H2 2.1.214 for format 2 and inspect actual JdbcConnection constructor: default user/password can both be empty. Download large binary DB with signed files/download, not files/contents. Running-server download is forensic only, never a deployable backup.
- AxVaults item arrays contain big-endian int slot count, then signed-short byte length and gzip NBT per nonempty item. Verify serializer bytecode before parsing. Patch only exact minecraft:custom_name/item_name/lore string spans; preserve all other decompressed NBT bytes and untouched compressed items exactly. Flatten supported text trees with inherited styles, preserving glyph fonts, colors, text and decorations. Reject unsupported component forms/events and optimized Python if assertions guard safety. Restrict tool to reviewed input hashes, separate empty staging directory, and no parser errors.
- Independently compare effective character styles and byte spans, then deserialize repaired items using real AxVaults on matching Paper. Verify native serialization roundtrip and repeated creative cloning of every repaired item. Current custom trim registry must be available: Nexo can regenerate its armor datapack empty in a minimal fixture lacking item configs; copy own registry under a distinct fixture datapack name. Never strip trim metadata to make tests pass.
- Stop live server, verify offline, cold-backup DB, export every row and require target rows match reviewed originals. Apply only selected rows transactionally on copy with original-value fences. Export/read back every row; unrelated rows must match. Upload nonloading staged DB, hash readback, recheck offline/original DB hash, rename backup and activate sequentially. Verify active DB hash before restart and fresh AxVaults loaded + Done after restart. Preserve original DB remotely and locally.
- State local creative/serialization proof separately from graphical glyph rendering and live player opening. Do not claim a new formatter patch when only historical item data was repaired. Generate new samples with actual MMOItems getItem and Nexo ItemBuilder.build, not handmade glyph items. Compare registry/catalog counts and disclose failed template dependencies separately.
- For permanent creative ingress protection, prefer a small Paper native-component companion over modifying premium JARs: normalize incoming InventoryCreativeEvent cursor name/item-name/lore with Adventure compact, calculate before cloning, preserve all nontext components, prior cancellation and amount. Validate complete component graph (children, translation args, hover text/entity names, selector/NBT separators) before and after recursion; reject excessive graphs without truncation. Recurse through native CONTAINER and BUNDLE_CONTENTS for nested text, with depth/item-count limits and copy-on-change; preserve slot positions including air gaps. Do not claim coverage for other embedded-item components or historical vault contents that never pass creative ingress. Test self-matching replacement RED and actual guard GREEN, fresh catalog native metadata/serialization, and actual creative packet loops. Compare effective character styles rather than raw text-tree equality because compaction changes structure.
- For nested-item native tests, compare component maps by type recursively: serialization may reorder component entries without changing metadata. Preserve ordering inside inventories, lore and attribute arrays. Restore all three text components before nontext equality, not only the deliberately deep custom name. Use a known named offline fixture identity for AxVaults Vault construction; a random unknown UUID can fail title placeholder replacement. Exercise actual AxVaults ITEM_ARRAY plus H2 save/load and player-open separately from raw Paper serialization.
- Optimize unchanged text with lazy lore copies, leaf-text fast paths and children-list reuse; skip prototype ITEM_NAME conversion unless isDataOverridden is true. Retain hover/translation/separator bounds and verify against Adventure 4.26.1 before older cached libraries in classpath. Measure thread CPU and allocation after warmup; allocated bytes per event are not retained RAM or whole-server usage. Do not promise zero CPU/RAM; no recurring scan means no scheduled scan work, not zero footprint.
- Wait for authoritative slot updates in client stress loops rather than fixed short sleeps; clear target before each clone to avoid same-item event short circuits. Preserve per-item IDs/results in files. Do not present missing custom skill/combat dependencies as fully tested gameplay.
