# Geyser custom inventory heads

Resolve scoped backend source and live Geyser target through panel inventory. Geyser may be on Velocity, not ECORPG. Scan backend menu/shop/plugin text configs via SFTP; include base64 textures, direct texture URLs, and bundled resources/class constants for hardcoded GUI icons. Save inventory/provenance per batch, dedupe by decoded skin hash, and validate URLs return PNG. Texture hashes are not necessarily 64 hex characters; preserve valid source hashes exactly. Never reconstruct malformed source tokens. Exclude world/player data, histories, caches and resource-pack asset trees; report these and unscanned JARs as coverage gaps. Player/leaderboard placeholders are dynamic and cannot be exhaustively mapped from static config. Do not claim all arbitrary player heads supported.

Use modern mapping `{"format_version":1,"skulls":{"skin_hash":["..."]}}` in a separate `plugins/Geyser-Velocity/custom_mappings/<scope>-player-heads.json`; legacy custom-skulls.yml migrates automatically. Preserve other mapping files/config and confirm custom-content/forced pack already enabled. Back up, validate, write and read back exact JSON.

Check fresh registered-skull count and generated pack; if absent, obtain explicit proxy restart approval because all network players disconnect. Restart only approved proxy, not backend. Require new boot Geyser `Registered N custom skulls as custom blocks`, `Finished creating skull resource pack`, Geyser Done, running state, source mapping unchanged and cache/player_skulls.mcpack present. Distinguish registration/pack verification from real Bedrock GUI rendering.

Use Paramiko remote.prefetch(size,max_concurrent_requests=32) for JAR reads; plain read is slow over WAN. Persist progress for large scans. Respect ZipFile overlapped-entry errors rather than bypassing zip-bomb checks. Large/unsupported JAR scans are reported gaps, not inferred clean.
