# Dungeon worlds and WorldGuard scope

1. Inspect dungeon mode and world binding in source plus runtime config before advising flags. PRIVATE instance worlds are temporary, plugin-managed copies; PUBLIC dungeons use an already-loaded, persistent world. Isolation hooks keyed to managed instance names do not bypass WorldGuard in PUBLIC worlds.
2. Resolve the exact world name used by the PUBLIC arena and inspect its WorldGuard `__global__` region plus overlapping regions at the affected coordinates. Do not assume a global flag wins over higher-priority region flags.
3. For MMO abilities, identify the owning plugin first. MythicLib documents the WorldGuard state flag as `mmo-abilities` (`MMO_ABILITIES` in its compatibility table); `DENY` blocks MMOItems/MMOCore skills when `plugins/MythicLib/config.yml` has `enable_flag_checks.skills: true`. This does not automatically disable AuraSkills or MythicMobs abilities. Check loaded plugin list and MythicLib's live config before claiming the flag works.
4. For an authorized PUBLIC-world change, target the actual persistent world, not a PRIVATE instance: from console run `rg info -w <world> __global__`, then `rg flag __global__ mmo-abilities -w <world> deny`. Read server log for WorldGuard's confirmation (`Region flag mmo-abilities set ... DENY`), run `rg save -w <world>`, and read back `rg info -w <world> __global__`. A Pterodactyl command HTTP 204 means queued, not proof of execution; confirm from console/log. Do not restart server for a region flag change. Check higher-priority overlapping regions before promising behavior across the entire dungeon; gameplay needs a player skill test.
5. If asked only whether the arrangement works, answer the scope question without changing flags, plugin config, or server state.
6. **Dungeon / Arena Entry Teleport Refusals (Vehicle / Seat Mounts & Case-Sensitivity)**: In Bukkit/Paper, `player.teleport()` returns `false` and fails if the player is currently sitting or inside a vehicle (e.g. GSit chairs, poses, custom mounts) or carrying passengers. When authoring or patching dungeon plugins (such as `NoeDungeon`), always force dismount and eject passengers (`if (player.isInsideVehicle()) player.leaveVehicle(); player.eject();`) prior to entry/respawn teleports, explicitly specify `PlayerTeleportEvent.TeleportCause.PLUGIN`, and compare dimension/world names with `equalsIgnoreCase` to prevent `Shared entry teleport refused` exceptions.
7. **ModelEngine & MythicMobs Boss Hitbox Desync / Invulnerability Pitfalls**:
   - **Never run continuous teleport loops** (e.g. `teleport @CasterSpawnLocation ~onTimer:5`) on active boss mobs; in Paper, repeated teleports desync client raycasts, break server bounding box interpolation, and cause weapon/projectile hits to pass through. Anchor stationary bosses via `MovementSpeed: 0`, `KnockbackResistance: 1`, and `AIGoalSelectors: - clear`.
   - **Base Entity Type matters**: Tiny base entities (e.g. `silverfish`, 0.4x0.3) leave huge vertical model areas unhittable by server raycasts. Use `IRON_GOLEM` or suitably proportioned entities with `MovementSpeed: 0` so the core bounding box covers the visual torso.
   - **Visual Dummies must disable hitboxes**: Auxiliary decoration dummies (e.g. base stands, VFX holders) summoned at the boss location must have `h=false` (or `hitbox=false`) in their `model{}` mechanic and `Collidable: false`; otherwise their invincible hitboxes intercept player attacks aimed at the boss.
   - **Bound spawn immunity duration**: Never set unbounded or massive potion duration (e.g. `duration=99999`) for spawn resistance. Use bounded timeouts (e.g. `duration=100`, 5s) so bosses never get permanently stuck in godmode if a trigger fails.
