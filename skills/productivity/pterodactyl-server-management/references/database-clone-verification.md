# Read-only source database cloning

- Inventory both servers with `/databases?include=password`, power state, active JARs and actual plugin connection configs before writes. Distinguish server-owned DBs from shared network DBs; ask before isolating LuckPerms because separate ranks stop network sync.
- Preserve source files, power and DB data. Offline game state does not prove DB quiescence: other servers, web bridges or stale processes can still write. Use `--single-transaction` for InnoDB and promise snapshot fidelity only unless every writer is paused with permission. Never kill source DB sessions to force consistency without authorization.
- Back up every source and target DB plus original target configs privately before import. Empty destination DBs allow additive CREATE/INSERT; reject nonempty targets rather than DROP/TRUNCATE or replay a partial import blindly. Recovery inspects exact target tables and verifies already imported DBs first.
- Use existing `mariadb` and `mariadb-dump`; their CLI flags differ. This host's dump rejects `--connect-timeout=30`, so apply that flag only to `mariadb`. Use MYSQL_PWD in subprocess environment, not command arguments. Make backup directory 0700 and secret artifacts 0600; never print connection fields.
- Canonical dump options: `--single-transaction --quick --skip-lock-tables --skip-add-locks --skip-add-drop-table --skip-comments --skip-dump-date --skip-extended-insert --complete-insert --hex-blob --order-by-primary --no-tablespaces`. One-row INSERTs can import slowly; for large DBs use a separate extended-insert import dump captured from the SAME consistent transaction or safely batch the already captured canonical INSERTs without changing values. Never replace snapshot mid-migration silently.
- Verify target against exact captured dump, schema (SHOW CREATE TABLE), table set and exact COUNT(*). TABLE_ROWS is an estimate, not a verification count. Preserve migration/metadata tables. Treat later source changes separately from target mismatch; compare normalized full dump bytes and save hashes and per-table counts. Inspect triggers, routines, views and events before assuming table-only coverage.
- Change only connection scalars in target YAML via YAML node offsets; preserve comments, formatting, types, prefixes and all nonconnection values. Structurally assert parsed output equals original with only intended fields replaced. Stage over SFTP, verify bytes, activate sequentially with recoverable backups, then read back target and source configs. Leave shared LuckPerms config unchanged when requested.
- Deep config scan uses SFTP and prunes binary assets, libraries and plugin backups. Disclose pruned paths and local SQLite/H2/YAML/world data excluded from remote MySQL clone. Do not conflate DB fidelity with complete server/world migration or tested gameplay.
- Preserve originally offline servers. Runtime plugin-connectivity tests require an authorized start; static credential/DB/schema verification does not prove plugin startup compatibility. Report this boundary plainly.
- Startup may rewrite plugin YAML without changing connection fields; verify parsed credential scalars after runtime instead of requiring whole-file hash equality. Preserve before/after copies and inspect unrelated changes separately.
- Leaderboard plugins may update cache timestamps during smoke tests. If exact snapshot final state is required, restore backed-up target cache while offline, then compare full dump again. Check unique indexes before ON DUPLICATE KEY UPDATE: `ajlb_extras` has no unique key, so blind upsert appends duplicate rows. Restore that backed-up cache with transactional DELETE+INSERT only under approved target restoration scope, never touch source.
- Inspect actual root JAR and startup variable before a smoke start. A restored UniverseSpigot instance can contain `ULoader.jar` while `SERVER_JARFILE=server.jar`, causing no new latest.log. Ask before changing startup outside database scope. Read back `/startup` after `PUT /startup/variable` with explicit key/value.
- A Paper loader exception can interrupt provider discovery and leave many present JARs unregistered. A successful Done with only a subset of plugins is not DB plugin verification. Check actual Java/classfile compatibility and plugin list; never install replacement dependencies merely because discovery says they are missing. Changing Java requires approval; use `PUT /settings/docker-image` with explicit `docker_image` and read back server attribute `docker_image` (not `container.image`).
