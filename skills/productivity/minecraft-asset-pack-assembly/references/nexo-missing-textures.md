# Nexo missing texture diagnosis

- Compare generated ZIP paths to model texture and particle refs before declaring files missing. Fallen Angel models can have correct hcs_fallen primary textures but typo hcs_vallen particle texture; repair both source model JSON particle refs, not generated atlas or duplicate namespace aliases.
- Audit all related ModelEngine animation-frame blueprints when one missing texture is reported. Nexo may report only first model using shared missing key. Awakened Warrior strike_of_fury variants had embedded red sword texture with namespace=minecraft, folder=awakened_warrior_texture, while exported PNG lived under modelengine:entity/models. Correct namespace/folder on every matching source texture while preserving elements, animation and source data; regenerate ModelEngine before Nexo and check again.
- Nexo 1.19.1 auto-detects custom armor from item IDs ending _helmet when Pack has texture-generated model, even for material SUGAR. For a flat icon such as aquamarine_helmet, retain ID/material/CMD and provide explicit Pack.model plus source JSON with original layer0; do not invent missing armor-layer PNG or rename item IDs. Exact NexoMeta bytecode sets generateModel false when Pack.model exists, bypassing automatic CustomArmorTextures fallback.
- Verify source bytes after deployment, fresh Nexo reload completion with zero missing-texture warnings, and resolved references inside generated ZIP. Check item icon/CMD preservation independently. Do not claim rendered client verification from static checks.
- Correct resource-location strings after parsing JSON: missing minecraft namespace is implicit, so literal search for minecraft: may miss bare awakened_warrior_texture/... refs. Repair explicit and implicit forms and rerun reference resolver on delivered ZIP; preserve all unrelated entries and compatibility overlays.
- Strip Blockbench `#missing` faces on 2D planar items: zero-thickness models (where `from.z == to.z`, such as cards or flat plaques) exported from Blockbench often assign `texture: '#missing'` to untextured side faces (`east`, `west`, `up`, `down`). Vanilla Minecraft fails quad texture resolution on unmapped `#missing`, rendering the entire item as magenta/black checkerboard. Remove zero-area side faces leaving only active textured faces (`north`/`south`), and add fallback `"missing": "<namespace>:<texture>"` and `"particle": "..."` to the model's `"textures"` block.
- Verify custom namespace texture atlas registration: in Minecraft 1.19.3+, every custom model texture in a non-vanilla namespace must be registered in `assets/minecraft/atlases/blocks.json` (and version overlays like `nexo_1_21_11/assets/minecraft/atlases/blocks.json`) via `{"type": "single", "resource": "<namespace>:<path>"}`. Textures omitted from `blocks.json` are never stitched into `atlas/blocks.png`, causing silent in-game magenta/black rendering even when PNG files physically exist in the archive.
