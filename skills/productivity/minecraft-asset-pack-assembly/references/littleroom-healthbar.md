# Littleroom healthbar pack inspection

- Distinguish overhead TextDisplay health bars from screen-top vanilla BossBar. The inspected v1.0 package uses MythicMobs HEALTHBAR_ENTITY text_display with minecraft:healthbar font, not BossBar API.
- Disable optional features under HEALTHBAR_ENTITY.Variables in mobs/healthbar.yml: show_damage_numbers: string/false, show_status_effects: string/false, display_level_on_health_bar: string/false; show_entity_name: string/false for bar only. Damage skill checks show_damage_numbers before summoning its TextDisplay and armor stand.
- Preserve original ZIP. Inspect exact version before applying recipes: website revision and local package may differ.
- Read vendor readme before activation. Direct `/mm mobs spawn HEALTHBAR_GLOBAL_LISTENER` avoids optional Crucible item path. Listener applies world-wide checks; do not activate it when user intends only selected bosses without adapting targeting.
- Warn before activating stock listener: its init changes sendCommandFeedback gamerule, force-loads origin chunk, teleports itself to origin and purges prior bars/listeners. VANILLAMOBS.yml is optional and alters vanilla entity definitions; exclude for boss-only installs.
- For ModelEngine, vendor requests p_hpbar bone, ride=true in model mechanic, and matching MythicMob ID/model filename. Verify actual mounted entity selector and runtime before declaring success.
- For selected-mob-only setup, attach start skills only to an explicit combat-ID allowlist; exclude VFX, hitbox helpers, templates, pets and vanilla overrides. Use explicit actual model IDs for mountmodel rather than caster type. Preserve all original combat skills and model geometry/animation. All frame variants can use separate literal font tags; nested font-name placeholders produced empty text in MythicMobs 5.13.0 tests.
- Diagnose bitmap healthbar centering from per-cell alpha bounds and actual glyph advance: Minecraft removes trailing transparent columns from advance but retains leading padding, shifting padded artwork right under CENTER alignment. Check every frame/stage; changing world X cannot reliably fix camera-facing text. Horizontal cell cropping must preserve vertical cell height/render scale; decorative heart bounds differ from fill bounds, so state which center is intended. Display names require explicit default-font span, reset, then separate bar-font row; never render names inside A–P healthbar font. Verify actual resolved components and client screenshot before deploying.
- For named overhead bars, cache parent Display in one TextDisplay, default font on name line and literal healthbar font on second line with `<&nl>`. Delay child parent-variable lookup two ticks: onSpawn can precede parent assignment and otherwise caches UNDEFINED. Convert legacy `&a` colors to MiniMessage before composing tags; mixed legacy/name content caused settext failure. Test all mapped names in native runtime, not only uncolored Pikeman.
- Crop each 64x16 atlas cell to the frame's union horizontal alpha bounds across all16 stages; retain16px height so bitmap scaling stays unchanged. Tested ascent9, translation0,0.4,0, CENTER alignment/billboard, one TextDisplay: visible name above centered bar with helmet gap in1.21.11. Preserve decorative frame pixels and unrelated ZIP entries; verify full/halfHP from front and side, not merely glyph existence. Changing atlas requires distributing corrected pack, YAML reload alone cannot fix player rendering.
- For per-model clearance corrections sharing frame types, set child display translation after mount in that parent's start skill, not global frame translation. Verified scale1.2/default Y0.85, Hollow Keeper Y3.0 and Slime Cuboss Y1.8 on1.21.11 with unobscured screenshots. These YAML-only adjustments do not require new resource-pack assets; existing active displays may require respawn/start reinitialization.
- Do not solve animated jumping by raising every label globally. Keep ordinary labels close to head; inspect the animated body hierarchy for jumping mobs and attach only their healthbar seat to the moving parent. A reparented slime seat needs live movement verification; valid JSON and reload cannot prove visual clearance throughout animation. Keep mesh/texture/animation data unchanged. Spawn and onLoad have different model-ready timings; preserve onLoad margin for vendor delayed model creation rather than dropping both delays indiscriminately.
- Validate vertical anchors against visible animated geometry, not hitbox height alone. Hitbox+2 produced crown overlap on Hollow Keeper and embedded-weapon overlap on Slime Cuboss despite a passing Pikeman screenshot. Inspect each model silhouette/pose; report obscured labels rather than claiming universal placement from one knight.
- Test ModelEngine passenger attachment with ModelEngineAPI.getMountPairManager().getMountedPair(UUID), not Bukkit isInsideVehicle: virtual model seats can be registered while Bukkit reports false. Keep isolated test chunks loaded and fixture mobs persistent or no-player despawn invalidates counts. Verify full/half/low/healed HP and cleanup on actual plugin runtime.
- Use explicit <= upper healthpercent thresholds and > lower thresholds with installed RangedDouble semantics; plain < excludes exact boundary including full HP. Prefer changed-stage-only settext and bounded per-bar timers over a global world entity scan.
- Audit skill references and health thresholds. Inspected v1.0 calls undefined HEALTHBAR_GLOBAL_reset_player_vars and health_11 upper threshold 0.756875 overlaps prior ranges. Report these, do not ship unchanged as verified.
- When Nexo regenerates custom font JSON, allow only the observed appended reference provider `{"type":"reference","id":"nexo:shift"}` during semantic comparison; preserve original bitmap providers and exact PNG bytes. Raw byte equality can fail despite intended Nexo import behavior.
- For modern standalone QA packs, include mandatory min_format/max_format alongside pack_format; a 1.21.11 client rejected pack_format 75 without those fields and silently removed the pack from options. Verify ResourceManager lists the candidate before evaluating visuals.
- User rejected flat polygon healthbar themes as substantially less detailed than vendor textures. Preserve authored pixel clusters, bevels, material shading and frame dividers; recolor brightness hierarchy and add ornaments only around retained structure. Do not substitute generic rectangles/crowns for textured artwork or call increased ornament count equivalent detail. Deliver original-versus-revision preview for approval before another live visual replacement after rejection.
- Theme only frame artwork when gradient_solid must remain: preserve the original x15..46/y7..9 HP pixels in every64x16 source cell, assert all16 stages unchanged, and crop consistent alpha bounds before font export. Scope themed display types per mapping rather than overwriting shared old fonts; retain old-child cleanup when switching styles. Preserve every unrelated ZIP entry and warn that server activation precedes player download if external distribution cannot be updated.
- Use Nether/crimson horns for Aloc, color-matched dripping slime frames for Cuboss, gold crowns with blue/red heraldry for Historical, cursed dark frames for Dreadlands, and bone/soul frames for Hollow Keeper when this user's themed healthbar style is requested.
