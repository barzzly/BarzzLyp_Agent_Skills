# Named resource-pack variants

- Resolve whether the request is metadata-only naming or actual optimization before building. For metadata-only HDResourcePack, OPResourcePack and SPResourcePack, preserve identical assets and compatibility metadata; change only pack.description in pack.mcmeta and ZIP filenames. Exact descriptions: HighReso Resources Pack Noesantara; Optimize Resources Pack Noesantara; SuperOptimize Resources Pack Noesantara. Use the same blue gradient for all three. Names do not imply actual optimization or higher-resolution assets. When a full corrected pack is requested, integrate verified additive fixes into each complete archive rather than requiring an extra overlay ZIP; preserve source archives and distinguish local deliverables from server distribution.
- Encode blue description gradient as vanilla JSON text components with per-character hex colors from #0038FF to #90E0F0, not MiniMessage tags; pack metadata does not parse plugin MiniMessage.
- When passing source ZipInfo to writestr, pass copy.copy(entry). writestr mutates offsets and sizes; reusing source entry objects corrupts in-memory source lookup and causes false overlapped-entry failures during verification.
- For actual three-tier optimization, derive every tier from the selected current source: HD retains original asset bytes; OP may minify JSON and losslessly recompress PNG/ZIP; SP adds explicitly authorized lossy audio and, only with permission, texture reductions. Read `references/audio-pack-compression.md`. Preserve compatibility metadata and all asset paths; do not copy smaller historical textures into newer content by matching names. For a new source that largely matches a prior build, reuse old optimized member payloads only when old-source and new-source member bytes match exactly (not path/CRC alone); preserve all changed/new compatibility assets byte-for-byte. Verify OP PNG mode, dimensions, pixels and non-IDAT chunks; verify SP decoded PNGs, same roster, source-unchanged modern overlays, and ZIP CRC. Stage all three outputs before replacing, keep previous variants as backups, and report that lossy SP pixels/audio are inherited from the prior approved preset, not newly optimized assets.
- Verify CRC and identical archive member sets for every tier. Metadata-only copies must differ solely in `pack.mcmeta`; lossless tiers need semantic JSON, decoded PNG pixel/dimension and ancillary-chunk parity; lossy tiers need a per-asset change manifest and unchanged protected assets. Check exact description text/color endpoints and unchanged non-description metadata. Keep source untouched unless removal separately authorized.
- Measure final archive bytes against the requested unit, report both MB and MiB near a size target, and explicitly state any unmet target. Tier names and successful ZIP checks do not establish size compliance, improved FPS, or in-game rendering correctness.
