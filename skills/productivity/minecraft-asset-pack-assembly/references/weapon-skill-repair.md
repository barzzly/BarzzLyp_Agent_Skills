# MMOItems weapon skills and legacy VFX

- Inspect actual MythicLib schema: modern builds use `source: mythicmobs:<ID>` with `parameters`, not only legacy `mythicmobs-skill-id`. Index Mythic skill folders separately from mobs/items, which can share IDs. Match item ability IDs case-insensitively to registered handler IDs.
- Before declaring a linked skill absent, recursively inspect supplied nested ZIPs and parse top-level YAML keys in every vendor skill folder; display names and filenames may differ from the internal skill ID. Never replace a missing entry with a convenient unrelated skill merely to make registration succeed: that changes gameplay while hiding the omitted dependency.
- Restore omitted skill dependencies in order: recover the original entry and recursive callback skills; collect mobs referenced by summon, projectile and orbital mechanics; collect blueprint IDs from model/changepart mechanics; validate the complete closure; deploy and read back; then restore the MythicLib mapping. Match references by mechanic and attribute, not a broad `t=` regex, because condition filters and potion types are not spawn dependencies. Namespace imported skills/mobs and their matching references to avoid global collisions, but preserve blueprint IDs, aura names and original gameplay values. Import only the needed closure rather than an entire unrelated class pack. Parse generated YAML/JSON and leave a runnable closure check; verify native model generation and `iazip` completion separately from player cast success.
- Preserve old MMOItems ability IDs by adding narrowly scoped MythicLib aliases to verified original skill entry points; this allows existing serialized abilities to resolve. Do not map every similarly named helper automatically: Bear_Form and Cetus_Parry can be gating stubs, while active Bear_Form_SKILL and Cetus_Parry_SKILL do the work. Read full trigger chain. Items generated while abilities were missing may lack serialized ability data and require carefully verified native refresh; never wipe player inventories.
- On MythicMobs 5.12 and 5.13, legacy `equip{item=name:0}` may silently leave armor stands empty. Use documented `equip{item=name HAND}`, `HEAD` for legacy 4, and `OFFHAND` for legacy 5. Reproduce native equipment NBT before/after; do not blame PNGs when all CMD models/textures exist. Limit bulk replacements to actual equip attributes and relevant weapon configs, retaining delays and models.
- For requested damage nerfs, trace exact active weapon skill chain and scale damage mechanics once server-side so old serialized items also receive the change. Preserve base attack, VFX, hit counts, healing and unrelated weapon modes unless requested. Test each modified formula ratio and reverse-normalize parsed YAML to prove no other semantic edits. Distinguish configured raw reduction from measured post-defense DPS; reload success is not combat balance proof.
- TIMER/castinstead wrappers may bypass cooldown on their outer skill. Put a persistent, finite aura lock and explicit Cooldown on the actual damaging child, reset charge stacks there, and preserve polling interval. Remove only unwanted self-immunity mechanics, not VFX entity Invincible flags. Bound click skills both in MMOItems and MythicMobs so existing items with old cooldown values remain protected.
- Use native `mi drop SWORD <ID> <world> <x> <y> <z> 100 1 0` at a verified empty, temporarily force-loaded test cell to validate real item generation and serialized MMOITEMS_ABILITY fields without touching player inventories. Capture UUID and clean exact fixture entities, then verify no leftovers and force-load restoration. This is build proof, not player casting/combat proof.
- Panel API latency can exceed 9-tick VFX lifetime. For equipment tests, use uniquely named temporary copies with only removal lifetime extended, preserve actual equip sequence, then remove fixtures and reload. Never lengthen production VFX merely for diagnostics.
- For a reported cast failure, read the live item template and MythicLib mapping, then inspect the selected item's serialized ability fields and exact MythicMobs entry/child conditions. A handler appearing in `mi list ability` proves registration only, not that existing items contain the ability or can cast it. Preserve the player's inventory; use read-only SelectedItem NBT and a controlled reproduction before changing mappings or refreshing items.
- Reload MythicMobs, then MythicLib, then MMOItems. `mi list ability` prints handler display names, not raw IDs; verify serialized item IDs separately. Audit INFO-level `Could not post-load` messages too, since missing unrelated built-in skills may not be WARN/ERROR. Verify exact deployed YAML readback and unchanged active JAR hashes. Label visual rendering, actual cooldown combat, old-item recovery and public resource-pack delivery gaps separately.
- Check vanilla sound pitch against exact-version implementation before editing: official Sound docs allow 0.01–2.0, and MM5.12 SoundEffect passes parsed pitch directly to Adventure. Artificer Flamethrower normal mode already uses `entity.blaze.shoot` at 0.1; Mecha mode calls Arcane_Bullets_FIRE_PRO with `entity.firework_rocket.blast` at 0.45. Neither low pitch nor sound omission is established by a silence report; preserve events until an isolated cast/client test identifies the cause.
- Inspect actual sound namespaces, not only event names: both unqualified calls and unqualified audio paths resolve under minecraft; explicitly qualify relocated audio paths. Preserve original audio hashes; recover omitted OGGs from supplied vendor archives, and report unavailable audio instead of silently substituting unrelated sounds. Check invalid `~onSpawnn` triggers, numeric equipment slots, BB5 detached group metadata with legacy ModelEngine importers, and duplicate MMOCORE/MMOITEMS alternative definitions. Never send restart while user has not authorized it; native-thread exhaustion can leave accepted console commands unexecuted, so require log/readback completion.
- For a multi-weapon bug report, trace each named item from its MMOItems ability ID through MythicLib registration, MythicMobs entry skill and every nested child/mob trigger; verify model ID references against registered ModelEngine blueprint IDs, and sound calls against both event JSON and physical OGG files. Fix only demonstrated broken links, parse edited YAML/JSON, and re-read the exact remote files before reload or `iazip`; a clean parser/reload is not proof of in-game model, sound, or skill behavior.
- Resolve duplicate MythicMobs IDs by registry (`skills`, `mobs`, `items`), including pack folders and repeated YAML keys; use YAML nodes rather than `safe_load` alone, which hides same-file duplicates. Namespace conflicting package-local definitions plus every reference in its skills, mobs and items, while preserving ModelEngine IDs, sounds and unrelated aura names. Prove token-only changes by reversing the rename and comparing original hashes. For MMOCORE/MMOITEMS alternatives, compare exact paired filenames, prove complete ID coverage and wrapper-body equivalence before disabling one; never disable shared `MMOITEMS-MMOCORE` essentials merely because its filename contains MMOCORE.
- For sound repairs, index nested vendor ZIP registries and OGG hashes before adding aliases. Minecraft defaults both unqualified event calls and unqualified `sounds.json` audio paths to `minecraft`, not the containing registry namespace. Preserve a source-proven event with explicit relocated audio namespace; restore referenced missing OGG byte-for-byte. Treat singular/plural event/file typos separately and validate both aliases. Empty unreferenced `mcmodels.*` watermark entries are not playable-event failures; report them separately from called events. Never replace a missing arrow-layer sound with an already-playing gunshot merely because both occur in a gun skill.
- Never place Pterodactyl API tokens in source snippets, shell history, or logs. Load credentials from an approved secret file/environment, redact tool output, and rotate immediately if a token is exposed; do not continue remote writes with a potentially compromised token.
- MythicLib skill keys are case-insensitive: Never include both `Skill_Name:` and `SKILL_NAME:` across or within `.yml` files in `MythicLib/skill/`. MythicLib warns `A skill with the same name already exists` and fails to load one of them. Standardize all keys to uppercase matching MMOItems ability references.
- Purge missing MMOItems custom lore formats: If weapons define `lore-format: <ID>` without a corresponding definition in `plugins/MMOItems/language/lore-format.yml`, MMOItems throws fatal errors during item generation (`Could not find lore format with ID ...`). Remove the line or configure the format.
- Safeguard mathematical placeholders on uninitialized variables: When iterating variables with `<caster.var.iteration>+1` in MythicMobs math expressions, uninitialized variables evaluate to `UNDEFINED`, throwing `Unknown function or variable 'UNDEFINED'` exceptions on exp4j. Always supply default values: `<caster.var.iteration;default=1>+1`.
