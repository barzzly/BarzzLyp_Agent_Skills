# MMOItems weapon skills and legacy VFX

- Inspect actual MythicLib schema: modern builds use `source: mythicmobs:<ID>` with `parameters`, not only legacy `mythicmobs-skill-id`. Index Mythic skill folders separately from mobs/items, which can share IDs. Match item ability IDs case-insensitively to registered handler IDs.
- Preserve old MMOItems ability IDs by adding narrowly scoped MythicLib aliases to verified original skill entry points; this allows existing serialized abilities to resolve. Do not map every similarly named helper automatically: Bear_Form and Cetus_Parry can be gating stubs, while active Bear_Form_SKILL and Cetus_Parry_SKILL do the work. Read full trigger chain. Items generated while abilities were missing may lack serialized ability data and require carefully verified native refresh; never wipe player inventories.
- On MythicMobs 5.13, legacy `equip{item=name:0}` may silently leave armor stands empty. Use documented `equip{item=name HAND}`, `HEAD` for legacy 4, and `OFFHAND` for legacy 5. Reproduce native equipment NBT before/after; do not blame PNGs when all CMD models/textures exist. Limit bulk replacements to actual equip attributes and relevant weapon configs, retaining delays and models.
- For requested damage nerfs, trace exact active weapon skill chain and scale damage mechanics once server-side so old serialized items also receive the change. Preserve base attack, VFX, hit counts, healing and unrelated weapon modes unless requested. Test each modified formula ratio and reverse-normalize parsed YAML to prove no other semantic edits. Distinguish configured raw reduction from measured post-defense DPS; reload success is not combat balance proof.
- TIMER/castinstead wrappers may bypass cooldown on their outer skill. Put a persistent, finite aura lock and explicit Cooldown on the actual damaging child, reset charge stacks there, and preserve polling interval. Remove only unwanted self-immunity mechanics, not VFX entity Invincible flags. Bound click skills both in MMOItems and MythicMobs so existing items with old cooldown values remain protected.
- Use native `mi drop SWORD <ID> <world> <x> <y> <z> 100 1 0` at a verified empty, temporarily force-loaded test cell to validate real item generation and serialized MMOITEMS_ABILITY fields without touching player inventories. Capture UUID and clean exact fixture entities, then verify no leftovers and force-load restoration. This is build proof, not player casting/combat proof.
- Panel API latency can exceed 9-tick VFX lifetime. For equipment tests, use uniquely named temporary copies with only removal lifetime extended, preserve actual equip sequence, then remove fixtures and reload. Never lengthen production VFX merely for diagnostics.
- Reload MythicMobs, then MythicLib, then MMOItems. `mi list ability` prints handler display names, not raw IDs; verify serialized item IDs separately. Audit INFO-level `Could not post-load` messages too, since missing unrelated built-in skills may not be WARN/ERROR. Verify exact deployed YAML readback and unchanged active JAR hashes. Label visual rendering, actual cooldown combat, old-item recovery and public resource-pack delivery gaps separately.
