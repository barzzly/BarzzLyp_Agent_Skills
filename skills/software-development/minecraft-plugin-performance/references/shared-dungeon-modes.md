# Shared dungeon modes

## User contract

- RukhDungeon user contract now has exactly two modes: PRIVATE preserves fresh per-party Hollow instances; PUBLIC is a persistent supplied open world combining optional scheduled boss, sequential waves, shared chest cooldown, and configurable GLOBAL/PERSONAL objectives. Accept legacy ARENA only at config load and save as PUBLIC with explicit `public.boss.enabled: true`; do not infer scheduling for old interactive PUBLIC bosses. Preserve accepted-death respawn timing and safety fences. PUBLIC global effects target joined participants, not all server players.
- Keep per-player objective completion and global shared-world lifecycle separate. Capture actor in death/interact/travel listeners, isolate action failures, preserve callback-selected objective branches, and retain personal progress through leave/rejoin. Freeze completion recipients and record outcome before reward callbacks; departure must not convert a win into failure. Scope boss-linked callbacks inside completion fence and preserve first-win eligibility.
- Compare final JAR entries with live bytes as well as source baseline. Source can omit an already-deployed WorldManager dead-player/nonempty-world unload guard; restore that exact live behavior rather than reverting it in a feature build. Verify normalized javap and packet compatibility separately from full gameplay.
- Wings SFTP may reject `posix_rename` overwrite. While server is stopped, rename old target to unique backup then rename staged verified bytes into place; on failure restore exact files and bring prior release online. Never claim deployment from upload alone.

## Implementation and verification checks

- Audit command, GUI, API and service admission separately; changing SessionService does not remove a leader-only gate in EnterCommand. Use one shared session per dungeon and index late joiners before teleport so foreign-session protection accepts legitimate entry.
- Separate participant actions from world actions when applying global objective effects. ObjectiveService calls onComplete with null actor; actor-default TELEPORT, player COMMAND and non-party rewards otherwise silently do nothing. Fan out participant actions once each, not gates/spawners/world commands once per player. Preserve PRIVATE action semantics.
- Attach late joins to countdown and boss bars without reinitializing timer/objectives/spawns. Rejoining must not reset claims or refund previously successful participants when another admission fails.
- Persist a safe pending exit before detaching failed late entrants. Test successful entry teleport followed by attachment failure and cancelled/redirected/throwing rollback; membership removal must not strand a player outside all cleanup indexes. Isolate UI removal failures from mandatory refund/exit/created-session cleanup; use nested finally and retain exact failed refund receipts without retrying ambiguous delivery blindly.
- Reconcile exact persistent owned entities on provided-world restart/chunk load; unlike disposable PRIVATE worlds, old owned bosses can survive disk reload. Do not delete unrelated vendor entities or create duplicate encounters merely because an entity is unloaded.
- Include arena start-world names in orphan-purge protection, not only template start/exit/lobby worlds. Validate overlaps across separate shared dungeon templates as well as within one template.
- Reference-count plugin chunk tickets across shared sessions, including failed-creation rollback: Paper allows only one ticket per plugin per chunk, so disjoint arena regions can still share one ticket. Publish fenced PREPARING ownership before synchronous chunk-load callbacks and reject cancelled creation after each callback; registration only after acquisition misses in-progress owners. Handle bosses moving outside pinned chunks and bounded replacement exhaustion; otherwise nonpersistent UNLOAD plus an active-round flag can stall all later scheduled spawns.
- Revalidate actual provider-returned entity locations plus registered RUNNING session identity before tagging ARENA boss ownership. On-spawn callbacks run before tags and may relocate the boss or clean its session; movement guards alone cannot cover that gap. Remove rejected live results without granting progress.
- Document interval origin, restart semantics, waiting-state behavior, empty arena persistence and reward eligibility. Keep scheduler main-thread and use existing shared timer; avoid per-dungeon threads and per-tick disk writes.
- Arm ARENA cooldown only from accepted tracked boss death, before external callbacks. Preserve first-discovery delay; active combat never advances deadlines. Use a separate completion latch as well as spawn reservation: nested completion must not release outer reservation or clear a new round. Snapshot winner/first-completion eligibility before committing outcomes and invoking reward commands, so callback departures cannot turn wins into failures or discard earned rewards.
- Treat nonpersistent ARENA whole-world unload as lifecycle risk: veto unload of exact registered shared supplied worlds until cleanup rather than interpreting ordinary chunk UNLOAD as death. Exhausted bounded replacement must abandon without rewards and schedule a full retry interval, not preserve an already-expired combat deadline.
- Measure shared-template indexing via production lookup with deterministic map-iteration counters; preserve PREPARING and terminal reservations, exact-owner unregister and clear invalidation. Stable chunk proxies with plugin-ticket set semantics let two genuinely created disjoint arenas test shared physical chunk ownership; copied reference sets alone do not prove native-equivalent ticket deduplication.
- At accepted ARENA death, freeze winner/first-completion eligibility and commit one outcome before reward commands can teleport or detach participants. Keep completion fenced through reward/event callbacks so nested spawn cannot create a new round that old cleanup erases. Test real listener death with command-induced departure, first-win reward, duplicate death and unaffected survivors; mutable recipient snapshots alone do not fix outcome ordering.
- Validate post-provider identity/location for PUBLIC regular mobs and bosses too, not only ARENA. Reject the whole new group before ownership after cleanup or out-of-bound relocation; validate translated PUBLIC gameplay points/regions before enable so accepted mandatory objectives cannot silently lack their spawn/gate.
- Use stable per-world-coordinate chunk test doubles with native per-plugin ticket deduplication. Exercise two real disjoint shared regions in one chunk; manually copying one session's Chunk object proves helper behavior, not acquisition or native ticket semantics.
- Bound optional ARENA combat lifetime from accepted spawn, never reset it during replacement. Fence returning in-flight replacement results by the original debt/round after provider callbacks: timeout can close a still-RUNNING shared session before spawn returns. Reuse the shared pulse for delayed evacuation and cancelled-teleport retries; block admission until all current participants detach, preserving exact configured pending exits.
- Verify installed Mythic removal semantics before adding cleanup workarounds. Mythic 5.13 ActiveMob.tick handles Bukkit dead-and-invalid via setDespawnedSync; ActiveMob.despawn deterministically runs DESPAWNED before removal, while ActiveMob.remove bypasses it. Aloc BaseDummy is a child through default summonerisparent, not `os` (onsurface). Native spawner removal clears registry and deletes its YAML but does not remove live mobs; read back both registry and disk, and separately reconcile exact associated entities.
- For optional ARENA combat limits, start lifetime only after accepted provider spawn, preserve it across replacement, and fence post-provider replacement results plus their continuation by original debt/round identity. RUNNING alone is insufficient because timeout keeps the shared session alive. Use the existing main pulse for closing/exit deadlines, deny admission while closing, and verify exact configured decimal exit separately from legacy centered BlockVec points.
- For opt-in worldwide PUBLIC ambient combat, keep ownership unchanged and gate both damage/targeting mismatches on an actual present RUNNING participant plus exact dungeon/world and native Mythic spawner group/type. Reject any raw session PDC key, tame ownership, and ActiveMob.getOwnerUUID().isPresent(); Mythic 5.13 returns its own Optl, not Java Optional, for ownership. Bind optional reflection once and fail closed without disabling ordinary spawning. Combat permission alone grants no objective credit, cleanup or replacement ownership.
- Before adding vendor despawn adapters, inspect installed Mythic removal fallback: 5.13.0-aad3f1c9 ticks dead/invalid Bukkit entities into setDespawnedSync and DESPAWNED skills. Direct Bukkit remove is not proof of skipped child cleanup; retain native behavior unless real evidence requires an adapter, and distinguish bytecode verification from live model/projectile cleanup.
- Parse Gradle test XML and enumerate actual cases before calling a build full regression verification. `build UP-TO-DATE` can retain only a previous filtered test invocation's XML; force an unfiltered `test --rerun-tasks` on final frozen source. Preserve earlier RED/GREEN results outside mutable build output.
- Compare feature changes against an archive of the initial dirty working tree, not only git HEAD; accumulated previously verified changes must remain intact. Keep one source/build owner until handoff and perform independent read-only review before release.
- When pushing plugin updates from a canonical development checkout where local HEAD lagged behind remote origin/main (which already holds prior release snapshots or intermediate sync commits), a 3-way git merge causes duplicate add/add conflicts across updated source files. Stage the verified local working tree to a temporary branch, switch and reset main to origin/main (`git checkout -B main origin/main`), selectively restore the updated trees (`git checkout <temp> -- src build.gradle.kts ...`), verify all headless tests pass without clobbering remote-only release archives, and commit cleanly on top of origin/main before pushing.
- For ARENA menus, format remaining respawn time as `Boss spawn: in X [units]` and live combat as `Boss spawn: Alive`. Evaluate `{boss_status}` to empty string in PRIVATE and PUBLIC modes so placeholder line-dropping suppresses the entry without blank dangling lines, and auto-inject after key/timer placeholders if disk configuration omits the tag.
- Administrative ARENA force-spawn (`/dungeon admin forcespawn <dungeon>`) must validate ARENA mode and enabled status, reject if a round is already active or evacuating, spawn via the configured provider, enroll eligible players, and set `startTimeMillis` to now. If spawn fails, restore the full respawn interval. Tab completion must suggest valid dungeon IDs.
- Retain a permanent `participants` set in `DungeonSession`: `eliminate` detaches participants from `session.players()` before invoking `fail` or `stopRun`. If the last player dies, `session.players()` is already empty; `notifyPlayers` must fall back to `session.participants()` so solo or wiped parties reliably receive `completion.failure` (`Dungeon failed.`) instead of silent termination.
- Bypass `cleanupGraceTicks` when all players have departed: grace ticks exist to give live players time to collect loot or evacuate. If `session.players().isEmpty()` on failure/stop, invoke `cleanup(dungeon, session)` immediately rather than holding the private session in `FAILED` with 0 players. Lingering empty sessions appear hung in operator session tools.
- Label empty persistent arena sessions `[IDLE]` in administrative listings and menus: public ARENA worlds remain registered 24/7 without active players. Labeling an empty, non-combat session as `[RUNNING] players=0` misleads operators into treating normal standby worlds as stuck runs.
- Beware in-memory template serialization during lifecycle commands: disabling a dungeon (`rd disable <id>`) writes the in-memory cached template back to disk (`dungeon.save()`). Modifying YAML directly on disk (e.g. toggling `boss-bar: false`) while the dungeon is cached in-memory will be overwritten if disable or save is called before reloading. Disable first, edit YAML on disk, reload, then re-enable.
