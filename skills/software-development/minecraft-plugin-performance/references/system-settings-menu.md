- Menu Typography Rule: In Paper / Adventure Component API, ItemStack display names and lore in vanilla Minecraft automatically default to ITALIC unless explicitly set to `decoration(TextDecoration.ITALIC, false)`. Converting legacy strings (`&f...`, `&e...`, `&7...`) or MiniMessage into ItemMeta without explicitly clearing italics causes all titles and lore lines to render slanted/italic in-game. ALWAYS wrap or prepend: `Component.empty().decoration(TextDecoration.ITALIC, false).append(LegacyComponentSerializer.legacyAmpersand().deserialize(str))` or `.decoration(TextDecoration.ITALIC, false)` so menu items render crisp and upright.
- Client-Side Nametag Hide Semantics: When a player toggles nametags to OFF (hide), only that player's viewpoint must be suppressed (hide other players' nametags from them, and hide their own personal nametag from themselves). Never invoke `clearViewers()` or disable broadcasting (`setShowingOwnNametagToOthers(false)`), because other players who have nametags enabled must continue to see this player's nametag.
- Packet-Based Personal Nametag (Lunar Client style): When showing player's own nametag via virtual packet entities (`TEXT_DISPLAY` / PacketEvents), the owner must be registered as a viewer (`entity.addViewer`), sent text metadata (`refreshViewerIfCached`), and mounted via `SetPassengers` packet (`showForOwner`/`showToViewer`). Merely updating coordinates without viewer registration leaves the packet entity unspawned on the client.
- Owner Relational Text Resolution: When resolving relational placeholder lines for a nametag row, explicitly include the owner in the viewer resolution list if `isEffectiveShowOwnNametag` is true; otherwise the owner's text cache remains null and text packets are never dispatched.
- Nametag Visibility Predicates: Differentiate 'hide other nametags' from personal nametag visibility (`!isOwnerViewer && isHiddenOtherNametags(viewer)`). External visibility toggles must never suppress personal nametag rendering.
- Join Preference Reconciliation: Packet reconciliation on player join must provide an explicit `else { showToOwner(player); }` branch; checking only `!isEffectiveShowOwnNametag -> hide` never initializes virtual nametag packets for joining players.
