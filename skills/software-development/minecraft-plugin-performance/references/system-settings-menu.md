- Menu Typography Rule: In Paper / Adventure Component API, ItemStack display names and lore in vanilla Minecraft automatically default to ITALIC unless explicitly set to `decoration(TextDecoration.ITALIC, false)`. Converting legacy strings (`&f...`, `&e...`, `&7...`) or MiniMessage into ItemMeta without explicitly clearing italics causes all titles and lore lines to render slanted/italic in-game. ALWAYS wrap or prepend: `Component.empty().decoration(TextDecoration.ITALIC, false).append(LegacyComponentSerializer.legacyAmpersand().deserialize(str))` or `.decoration(TextDecoration.ITALIC, false)` so menu items render crisp and upright.
- Client-Side Nametag Hide Semantics: When a player toggles nametags to OFF (hide), only that player's viewpoint must be suppressed (hide other players' nametags from them, and hide their own personal nametag from themselves). Never invoke `clearViewers()` or disable broadcasting (`setShowingOwnNametagToOthers(false)`), because other players who have nametags enabled must continue to see this player's nametag.
- Packet-Based Personal Nametag (Lunar Client style): When showing player's own nametag via virtual packet entities (`TEXT_DISPLAY` / PacketEvents), the owner must be registered as a viewer (`entity.addViewer`), sent text metadata (`refreshViewerIfCached`), and mounted via `SetPassengers` packet (`showForOwner`/`showToViewer`). Merely updating coordinates without viewer registration leaves the packet entity unspawned on the client.
- Owner Relational Text Resolution: When resolving relational placeholder lines for a nametag row, explicitly include the owner in the viewer resolution list if `isEffectiveShowOwnNametag` is true; otherwise the owner's text cache remains null and text packets are never dispatched.
- Nametag Visibility Predicates: Differentiate 'hide other nametags' from personal nametag visibility (`!isOwnerViewer && isHiddenOtherNametags(viewer)`). External visibility toggles must never suppress personal nametag rendering.
- Join Preference Reconciliation: Packet reconciliation on player join must provide an explicit `else { showToOwner(player); }` branch; checking only `!isEffectiveShowOwnNametag -> hide` never initializes virtual nametag packets for joining players.

## Packet nametag lifecycle and cache checks

1. Load native PDC preferences before session registration and tag creation. Keep viewer-side OFF separate from broadcasting; reuse existing storage rather than adding a competing DB. Exercise each preference's true/false roundtrip; headless PDC tests do not prove native save-to-disk or restart durability.
2. Fence delayed joins and creation/refresh completions with online status, exact Player-session identity, and current row/tag identity before committing on the owning scheduler. Clean quit/tracker state synchronously; a stale disconnect or completion must not delete or recreate a replacement session sharing the UUID. Include quit-before-create, immediate reconnect, stale completion, reload initialization, and pending-creation cleanup in runnable production-method regressions.
3. Serialize per-viewer show/hide/remove operations and reject spawn after tag removal. Use direct wrapper lookup during flush/eligibility checks rather than wrapper-creating getters. Clear departed viewer layout, forced text, placeholders and passenger state on quit/close; capture detached UUID/entity ID for async packet work and reject late callbacks from old sessions before allocating maps.
4. Restore cached or forced viewer text before respawn/reattachment and invalidate equality suppression when metadata must be resent: identical text values do not imply a newly spawned client entity already has that metadata. Test hide/show and reattachment with unchanged forced text. Bypass shared component caching for audience-dependent MiniPlaceholders unless the key includes the audience and appropriate invalidation; shared literal text can render differently per viewer.
5. Bound both global expression/component caches and per-player placeholder maps with capacity plus expiry. Preserve cache ownership and lifecycle cleanup; an expiring map without a maximum still permits burst growth. Test actual capacity and late-callback behavior rather than asserting Map field names. Report bounded retention and regression evidence, not a guarantee of zero possible leaks.
6. Freeze source after the sole build owner releases it, compare current tracked `git diff --no-ext-diff | sha256sum` with the review digest, then run build and every registered regression against final packaged bytes. A matching tracked diff does not cover untracked fixtures; inventory those separately. Static approval does not replace build/runtime gates, and delayed older reviews cannot override newer artifact evidence.
