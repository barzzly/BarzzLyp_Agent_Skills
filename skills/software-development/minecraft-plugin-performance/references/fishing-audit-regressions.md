# CustomFishing audit regression gates

- Trace caller cleanup before checking hook validity in delayed rewards. Normal success immediately destroys hook; delayed loot must survive that cleanup. Guard duplicate success before scheduling and preserve offline checks.
- Reject interactions with already-active totem core before block-ID resolution and world-pattern scans. Reuse world-aware SimpleLocation and retain late guard; test inactive/cancelled activation, another world, expiry/reactivation and input guards through real handler.
- Snapshot reward rod for item generation/size limits. Do not compare vanilla rods including damage after reel durability changes: normalize only damage for vanilla equality. Test multi-loot after stop, vanilla damage mutation, and swap to a different rod/material. Keep sizeless trash catchable; invalid configured bounds still fail closed.
- Test final generated size with `restricted-size-range: false` only in isolated fixtures when proving multiplier effects. Production default range clamping can legitimately cancel test multiplier; never modify user gameplay config to satisfy a test.
- Run catch harness alone on peaceful/invulnerable test player. Reload, another player, mob death, and dropped items contaminate XP/drop assertions. Reset fixture failure count per run; assert every named case plus final count. Log item identity and source when an item-presence assertion fails; a passing rerun does not establish the failure's cause or prove a production fix.
- Bag admission must cover cursor PLACE/SWAP, shift from bottom, number-key/offhand (`hotbarButton == -1`), and drag. Permit removal and ordinary bottom manipulation. Match fixture policy: default `can-store-loot: false` legitimately rejects cod.
- Check market final summed/multiplied amount and resulting earnings are finite before item clearing/reward. Per-item finite checks alone miss overflow. Test real GUI settlement leaves items/earnings unchanged.
- Use unique temporary file per JSON/YAML save, UTF-8, atomic replace with filesystem fallback, and finally cleanup. A shared `<uuid>.yml.tmp` lets concurrent writers overwrite/delete each other's data. Test another temp file survives, serialization failure retains old target, and failed replacement returns false.
- Compile test plugins against same Paper API version as runtime; old Spigot `InventoryView` ABI may differ. Unsafe-allocate real plugin implementation for standalone tests rather than repeatedly inventing incomplete abstract plugin stubs.
- Treat subagent summaries as unverified: require runnable tests and verify exact source diff. Reject untested lifecycle patches that publish competition before start then release lock; unload can interleave and orphan timer.
- Preserve async event contracts; separate Redis I/O from Bukkit scheduling only with explicit lifecycle tests. Do not label repository fully safe or Folia-compatible after Paper-only harness.
- Use one shared reentrant lifecycle monitor for manager-owned competitions instead of opposite manager/competition lock orders. Preserve queued replacement deadline when updating pending config; invalidate previous ranking-clear callback before starting replacement.
- Pause deterministic race tests inside the production timer body, not in a wrapper before entry; the latter only repeats a stale-callback test and cannot expose in-flight stop interleaving.
- Verify import failure through actual SQL method proxies for select/update/insert exceptions, serialization errors, zero-row results, and successful writes in each overriding provider. Bound future completion with a timeout. A source-token guard does not prove a future completes or command success is truthful; compile temporary mutations that remove guards to prove the tests reject hangs and false success.
- Resolve import paths with real-path containment and require regular files with expected extension. Test sibling-prefix traversal, absolute paths, file/directory symlink escape, and legitimate nested/contained-symlink inputs. Inspect sender restrictions before labeling a console-only import flaw player-exploitable.
- Inspect provider replacement conditions before changing storage reload logic. Same-type reload can retain provider while backend-type or Redis-enable changes replace resources; treat live backend migration separately, with offline players, backup/export and restart rather than an untested broad callback rewrite.
- Disable comparator-based TreeSet removal after mutable ranking keys escape or nonfinite scores enter (including arithmetic overflow); retain identity-scan fallback until clear. Test comparator collisions and public object-removal semantics, and do not advertise O(log N) full updates while name lookup remains linear.
- Test single-save failures separately from upsert in both AbstractSQLDatabase and SQLiteProvider: serialization, zero rows, SQL failure and executor rejection. Catch scheduling rejection outside execute so the method returns an exceptionally completed future instead of throwing before return; preserve exact lock/data/UUID bindings and provider-owned executor.
- Decode Base64 locally to validate values. Tool-output redaction may show `...` even when source contains complete valid textures; do not 'fix' redacted values.
