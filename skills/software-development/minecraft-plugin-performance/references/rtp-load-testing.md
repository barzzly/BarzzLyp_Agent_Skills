# Bounded RTP tests

- For a per-world view-distance override on current Paper, use `spigot.yml` `world-settings.resource.view-distance: 4` (not `resource/paper-world.yml`: Paper's per-world YAML has no view-distance field). Preserve `world-settings.default.view-distance: default`, global `server.properties` view-distance, and simulation distance. Back up the exact file, insert only the resource stanza, check readback, restart, then check fresh Done/state/log; idle TPS does not prove RTP improvement. Comparative 20-client RTP load needs explicit fresh authorization before running, even after a config-change request.
- Pregeneration is not chunk residency: BetterRTP 3.6.13 uses PaperLib async chunk load/teleport. Inspect Spark *matching RTP time window* and Chunky task state before tuning. `cancelled=true` in Chunky tasks does not by itself prove full pregen; check region coverage. PreloadRadius may be parsed but not actually called by installed JAR: grep bytecode call sites before treating it as a live setting. Under 20 concurrent resource-world RTPs, Spark's ServerChunkCache.tick/tickChunks samples and dispersed chunk ticking may dominate; a high max tick alone does not prove synchronous disk I/O. Preserve view/simulation distance, mob spawning, and Paper limits unless comparing controlled before/after under equivalent load; resource visibility or simulation cuts are gameplay tradeoffs. When players are online, obtain restart timing before deploying restart-only per-world config.
- Inspect live menu commands, BetterRTP cooldown/economy/preload settings, server player count, TPS and container limits before authorizing ramp. Noesantara uses `/betterrtp:rtp world resource` for direct provider invocation without DeluxeMenus alias interception. Keep existing cooldown/protection unchanged; distinguish accepted teleports from cooldown command rejections.
- Keep a stable credential file per registered test identity across aborted runs; generating a fresh secret for an already registered `NoeLoad` account yields `Password salah!`, not a backend admission fault. Never rotate existing credentials blindly. Proxy login success can be indicated by optional post-login `/premium <password>` advice instead of `Kamu sudah login!`. Wait for explicit auth response before transfer.
- Reuse dedicated NoeLoad identities only after verifying non-OP state and current backend absence. A password file entry does not prove account registration or current password validity: classify explicit `Kamu belum terdaftar!` separately from `Password salah!`, and require authenticated proxy state before `/server` transfer; otherwise a transfer timeout mislabels an auth failure as backend capacity. Use native proxy forceregister only after the unregistered response, then retry login; never overwrite an existing account with an unknown password or raise global registration limits.
- Ramp client joins before bounded RTP batches, verify actual backend membership and fresh client heartbeat, sample native spark tps, and abort on low TPS, memory ceiling, server errors or anti-cheat failures. Keep callbacks/protocol tick_end compatible with installed Mineflayer, and suppress idle arm swings in menus.
- Do not consider a generic physicsTick tick_end hook fully compatible with cross-world RTP: live teleports can still trigger Grim TickTimer. Abort and label the workload invalid when that occurs; never bypass anti-cheat. Evaluate fresh error windows even when membership assertions fail, so the first failure does not hide protocol faults.
- Serialize `whitelist add/remove` commands against Paper: parallel writes can corrupt `whitelist.json` into two overlapping JSON fragments. If corrupted, back up exact bytes, parse first complete array, preserve all unrelated/baseline identities, write clean JSON, `whitelist reload`, and read back before any further load test. Verify cleanup by ownership, not whole-whitelist equality when another operator adds a player during testing. Preserve unrelated additions and confirm every test-owned addition absent plus baseline entries intact. Never delete concurrent legitimate users to make a snapshot comparison pass.
- Velocity queue can delay `/server noerpg` beyond short fixed transfer retries; send transfer once and wait for confirmed backend membership, never treat queued status as backend admission. Probe login throughput before a large batch: same-IP proxy throttles can kick nearly every simultaneous join with `You are logging in too fast, try again later.` Keep whitelist/auth preparation concurrent if supported, but pace connection attempts under the gate rather than disabling production throttling; report admission limit separately from backend TPS or movement capacity. A third-party `stop`/restart during test invalidates run: abort, clean up owned names, wait for fresh `Done`, and do not infer load failure from process stop. Honor users already online and check whitelist behavior before rerun.
- Save each attempt separately; never mix prior bot events into a rerun. On abort, stop bot clients, then derive owned whitelist entries from fresh remote readback rather than successful API responses: a command can apply despite a 500 response. Remove only test-owned entries, retry transient API failures with another readback, and verify no test names online plus original whitelist/config. Retain dedicated account records; avoid dumping passwords or auth logs into chat.
- For large batches, collect each client's first successful RTP coordinate from join onward and distinguish unsolicited pre-command teleports from command responses; verify destination/world before sending another RTP, because duplicate commands can be denied by normal cooldown despite all clients having already teleported. Start a requested hold timer only after every client has successfully RTP'd and remains connected; sample membership and fresh heartbeat throughout the full interval. On an aborted run, keep natural account cooldown rather than bypassing it. If the backend stops or panel API fails, abort and preserve evidence; finish owned-whitelist cleanup after safe recovery, reading back exact names even if the bot process exited. Never report an incomplete hold as passed.
- Current bounded harness: Minecraft/monitoring/rtp-bots.cjs and run-rtp40.py. It is a live test tool, not permission to run stress traffic without a new user request. Generic RTP success chat plus coordinates does not establish client rendering or all-world coverage.
